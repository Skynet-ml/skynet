На этой странице показано, как начать первый запуск примерно за десять минут. Вы входите в систему, загружаете небольшой набор данных, заполняете четыре шага мастера и запускаете оптимизацию. В примере Skynet создаёт новый репозиторий, который распределяет обращения в поддержку по меткам, а затем улучшает его.

## Перед началом

Вам понадобятся:

- Аккаунт Skynet.
- Аккаунт GitHub. Skynet создаёт репозиторий в этом аккаунте.
- Файл CSV, JSON или Excel (`.csv`, `.json`, `.xlsx` или `.xls`). Каждая строка — один пример.
- Один или несколько входных столбцов, например `message`.
- Один столбец с ожидаемым выходом, например `label`.

> [!TIP]
> Используйте не меньше 5 строк. Если пар меньше 5, Skynet не выделяет тестовую выборку, и итоговая оценка считается на примерах, которые видел оптимизатор.

## 1. Вход

Войдите в Skynet. Подключите GitHub в разделе **Настройки → Коннекторы**. Затем откройте страницу отправки `/submit`.

> [!NOTE]
> На этой странице используются подписи уровня **Стандартный**. Уровень **С подсказками** использует более простые подписи, пропускает шаг «Оптимизатор» и выбирает **Auto** за вас. Уровень меняется в настройках.

## 2. Задача

Первый шаг — **Задача**. Он спрашивает: «Что вы хотите оптимизировать?»

1. В поле **Цель** опишите, что считается хорошим результатом. Пишите простыми словами, например: «Отнеси каждое обращение в поддержку к billing, bug или other».
2. Необязательно: в поле **Контекст** добавьте сведения, которые помогут оптимизатору.
3. Выберите **Создать новый репозиторий**. Введите имя, например `support-labels`, и выберите **Приватный** или **Публичный**.

Skynet создаёт репозиторий в вашем аккаунте GitHub. Ассистент пишет первое решение по вашей задаче и данным. Это решение — исходная версия. Если у вас уже есть код, выберите вместо этого **Использовать репозиторий**. Прочитайте [Запуск через мастер](/docs/guides/submit).

## 3. Входные данные

Второй шаг — **Входные данные**.

1. Выберите **Загрузите файл CSV, JSON или Excel** или **Выбрать из библиотеки**, чтобы использовать сохранённый набор данных.
2. В разделе **Как читать данные** назначьте каждому столбцу роль:
   - **Вход**: ваш код получает этот столбец.
   - **Выход**: ожидаемое значение. Его получает оценщик.
   - **Пропустить**: Skynet не использует этот столбец.
3. Оставьте для разбиения вариант **Использовать рекомендацию**. Для большинства наборов данных разбиение составляет 70% обучающей, 15% валидационной и 15% тестовой выборки.

Полные правила описаны в разделе [Наборы данных и разбиение](/docs/concepts/datasets).

## 4. Оптимизатор

Третий шаг — **Оптимизатор** («Оптимизатор, модели и бюджет»).

- Оставьте оптимизатор **Auto**.
- Выберите **Модель рефлексии**. Оптимизатор использует её, чтобы писать новые версии. Эта модель обязательна.
- В разделе **Бюджет** оставьте для **Макс. запусков оценщика** значение по умолчанию — 200.

Чтобы выбрать конкретный движок, прочитайте [Движки](/docs/concepts/engines).

## 5. Метрика и запуск

Последний шаг — **Метрика и запуск**. Ассистент пишет оценщик за вас. Вы можете его изменить. Оценщик получает путь к одной версии репозитория и один пример:

```python tab="scorer.py"
import importlib.util


def score(repo_path, case):
    spec = importlib.util.spec_from_file_location("serve", f"{repo_path}/serve.py")
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    got = str(module.serve(case["input"])).strip().lower()
    want = case["expected"]["label"].strip().lower()
    if got == want:
        return 1.0, {"feedback": "Correct label."}
    return 0.0, {"feedback": f"Expected '{want}', got '{got}'."}
```

`case["input"]` содержит столбцы с ролью «Вход» для одного примера. `case["expected"]` содержит столбец с ролью «Выход», ключ — имя этого столбца. В репозитории есть файл `serve.py` с `def serve(input)`. После запуска Skynet использует эту же функцию, чтобы обслуживать лучшую версию.

Затем запустите проверку. Проверка выполняет вашу настройку и ваш оценщик на исходной версии в песочнице. Начать запуск можно только после того, как проверка пройдёт успешно.

## 6. Запуск и наблюдение

На итоговом экране написано «Готово к запуску». На нём есть вкладки «Общее», «Данные», «Модели», «Бюджет» и «Награда». Проверьте настройки, затем запустите оптимизацию.

Чтобы следить за запуском, откройте его из списка оптимизаций. Skynet отправляет каждого кандидата в отдельную ветку вашего нового репозитория. Ветка `skynet/best` всегда указывает на лучшую версию. Как понимать оценки и победившую версию, описано в разделе [Чтение результатов](/docs/guides/results).
