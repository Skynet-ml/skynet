Мастер отправки настраивает и начинает запуск. В нём четыре шага: **Задача**, **Входные данные**, **Оптимизатор** и **Метрика и запуск**. Каждый шаг содержит один или несколько экранов. В этом руководстве описан каждый экран — от задачи до проверки и начала запуска.

> [!NOTE]
> Мастер показывает больше или меньше настроек в зависимости от уровня опыта: **С подсказками**, **Стандартный** или **Эксперт**. По умолчанию выбран уровень «С подсказками». Уровень меняется в разделе **Настройки → Учётная запись**, в пункте **Сколько показывать**. На уровне «С подсказками» некоторые подписи проще. В этом руководстве используются подписи уровней «Стандартный» и «Эксперт», а подпись уровня «С подсказками» указана в скобках, если она отличается.

## Шаг 1: Задача

### Что вы хотите оптимизировать?

Опишите задачу ассистенту в чате **Интервью о задаче**. Ассистент заполнит за вас два поля:

- **Цель** (С подсказками: **Задача**): что оптимизированный код должен делать хорошо.
- **Контекст** (С подсказками: **Дополнительный контекст**): контекст, ограничения и то, как выглядит хороший результат.

Оба поля можно редактировать. Ассистент не перезаписывает ваши правки.

### Откуда берётся код

Skynet — это Optimize Anything: каждый запуск оптимизирует репозиторий. Выберите один из двух вариантов:

- **Использовать репозиторий**: оптимизировать код в подключённом репозитории GitHub.
- **Создать новый репозиторий**: Skynet создаёт новый репозиторий GitHub в вашей учётной записи. Ассистент пишет первое решение по вашей задаче и данным. Это решение становится исходной версией.

Перед началом подключите GitHub в разделе **Настройки → Коннекторы**.

### Использовать репозиторий

Заполните поля:

- **Репозиторий**: выберите репозиторий или укажите его в виде `owner/name`.
- **Коммит**: SHA из 40 символов. Оставьте поле пустым, чтобы использовать последний коммит ветки.
- **Пути, которые оптимизатор может менять**: по одному файлу или папке на строку. Точка означает весь репозиторий.
- **Команда установки**: выполняется в каждой свежей копии репозитория перед оценкой. Если оставить поле пустым, Skynet сам найдёт команду.

### Создать новый репозиторий

Заполните поля:

- **Название**: название нового репозитория. В вашей учётной записи GitHub не должно быть репозитория с таким названием.
- **Приватный** или **Публичный**: кто может видеть репозиторий на GitHub.

Skynet отправляет каждого кандидата в отдельную ветку. Ветка `skynet/best` указывает на лучшую версию.

## Шаг 2: Входные данные

### Данные

Добавьте примеры для запуска. Вы можете:

- Загрузить файл CSV, JSON или Excel.
- Выбрать набор данных из библиотеки.

Прочитайте [Наборы данных и разбиение](/docs/concepts/datasets) и [Подготовка набора данных](/docs/guides/datasets).

### Как читать данные

Ассистент читает данные и предлагает, как их использовать. Проверьте его выбор:

- Отметьте каждый столбец как вход, ожидаемый выход или пропускаемый.
- Если столбца-выхода нет, Skynet использует первую строку как один вход.
- Задайте разбиение на обучающую, валидационную и тестовую выборки. Сумма долей должна быть равна 1.

> [!WARNING]
> Пока на шаге **Входные данные** есть ошибки, следующие шаги недоступны. Исправьте проблемы, которые показывает мастер, и продолжайте.

## Шаг 3: Оптимизатор

На уровне «Стандартный» у этого шага один экран. На нём показаны оптимизатор, бюджет и, если нужно, модели. На уровнях «С подсказками» и «Эксперт» у шага три экрана: **Оптимизатор**, **Модели** и **Бюджет**.

### Оптимизатор

Мастер показывает только оптимизаторы, которые подходят вашей задаче и входным данным. По умолчанию выбран **Auto**. При желании выберите другой оптимизатор. Прочитайте [Движки](/docs/concepts/engines) и [Как работает оптимизация](/docs/concepts/optimization).

### Модели

- **Модель рефлексии**: модель, которая читает оценки и обратную связь и пишет следующих кандидатов. Для оптимизатора с агентом-программистом это модель агента.
- **Модель задачи**: модель, которую код вашего репозитория и ваш оценщик могут вызывать через шлюз моделей Skynet. Прочитайте [Как работает оптимизация](/docs/concepts/optimization).

### Бюджет

Задайте, как долго запуск может продолжать попытки и сколько он может потратить:

- **Макс. запусков оценщика** (С подсказками: **Макс. попыток**): максимальное число кандидатов, которые оценит Skynet. Некоторым оптимизаторам нужно минимальное число.
- **Остановиться при оценке** (С подсказками: **Остановиться раньше, когда оценка достигнет**): запуск останавливается, когда версия достигает этой оценки.
- **Макс. итераций** (С подсказками: **Макс. раундов**): показывается для оптимизаторов, которые это поддерживают.
- **Лимит расходов**: максимум, который может потратить запуск. По умолчанию — $5 или сумма **Нужно для старта**, если она больше. Также можно выбрать **Без лимита**.

Мастер не даёт продолжить, если лимит или ваш баланс меньше суммы, необходимой для старта. Прочитайте [Бюджеты и оплата](/docs/concepts/billing).

## Шаг 4: Метрика и запуск

### Оценщик

Напишите `scorer.py`. Он определяет `score(repo_path, case)` и возвращает оценку с обратной связью. Ассистент может написать его за вас. Прочитайте [Метрики и оценщики](/docs/concepts/scorers).

В репозитории может быть файл `serve.py` с `def serve(input)`. После запуска Skynet использует его, чтобы развернуть лучшую версию. Прочитайте [Чтение результатов](/docs/guides/results).

### Секреты

Добавьте секреты, например ключи API, которые нужны вашему коду. Каждый секрет попадает в ваш код и ваш оценщик как переменная окружения с тем же именем. Агент-программист их не видит. Skynet скрывает их значения в логах.

### Проверка

Проверка (С подсказками: **Тестовый запуск**) выполняет установку и ваш оценщик на исходной версии в песочнице. Она проверяет:

- сигнатуру оценщика,
- команду установки,
- возвращаемое значение оценщика на примерах.

Нажмите **Проверить** (С подсказками: **Протестировать**). Начать запуск можно только после того, как проверка пройдёт. Если после успешной проверки вы измените оценщик или установку, запустите проверку снова.

> [!TIP]
> Откройте каждый пример, чтобы увидеть его оценку и обратную связь. Хорошая обратная связь даёт оптимизатору больше информации, чем одна оценка.

### Запуск по расписанию

После успешного завершения оптимизацию можно повторно запускать по расписанию. Каждый цикл по расписанию начинается с текущей лучшей версии репозитория. По умолчанию — **Выкл.**

### Готово к запуску

Последний экран показывает сводку на пяти вкладках: **Общее**, **Данные**, **Модели**, **Бюджет** и **Награда**. Проверьте настройки, затем запустите оптимизацию.

Сводка также показывает видимость запуска. Новые запуски по умолчанию публичные. Позже видимость можно изменить в диалоге **Доступ и конфиденциальность** на странице запуска. Прочитайте [Общий доступ и публикация](/docs/guides/sharing).
