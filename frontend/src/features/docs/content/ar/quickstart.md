توضّح هذه الصفحة كيف تبدأ أول تشغيل لك في نحو عشر دقائق. تسجّل الدخول، وترفع مجموعة بيانات صغيرة، وتملأ خطوات المعالج الأربع، ثم تبدأ التشغيل. في المثال، ينشئ Skynet مستودعًا جديدًا يصنّف رسائل الدعم إلى تسميات، ثم يحسّنه.

## قبل أن تبدأ

تحتاج إلى:

- حساب Skynet.
- حساب GitHub. ينشئ Skynet المستودع في هذا الحساب.
- ملف CSV أو JSON أو Excel (`.csv` أو `.json` أو `.xlsx` أو `.xls`). كل صف هو حالة واحدة.
- عمود إدخال واحد أو أكثر، مثل `message`.
- عمود واحد للمخرج المتوقع، مثل `label`.

> [!TIP]
> استخدم 5 صفوف على الأقل. مع أقل من 5 أزواج، لا يحتفظ Skynet بمجموعة اختبار، فتأتي الدرجة النهائية من حالات استخدمها المُحسِّن.

## 1. تسجيل الدخول

سجّل الدخول إلى Skynet. اربط GitHub في **الإعدادات ← الموصّلات**. ثم افتح صفحة الإرسال على `/submit`.

> [!NOTE]
> تستخدم هذه الصفحة تسميات المستوى **قياسي**. يستخدم المستوى **موجَّه** تسميات أبسط، ويتخطّى خطوة المُحسِّن، ويختار **Auto** نيابةً عنك. غيّر المستوى من الإعدادات.

## 2. المهمة

الخطوة الأولى هي **المهمة**. تسألك "ما الذي تريد تحسينه؟"

1. في **الهدف**، اكتب ما هي النتيجة الجيدة. استخدم كلمات بسيطة، مثل "صنّف كل رسالة دعم إلى فوترة أو خلل أو أخرى."
2. اختياري: في **الخلفية**، أضف سياقًا يساعد المُحسِّن.
3. اختر **إنشاء مستودع جديد**. أدخل اسمًا، مثل `support-labels`، واختر **خاص** أو **عام**.

ينشئ Skynet المستودع في حساب GitHub الخاص بك. يكتب المساعد حلًا أوليًا من مهمتك وبياناتك. هذا الحل هو نسخة البداية. إذا كان لديك كود بالفعل، فاختر **استخدام مستودع** بدلًا من ذلك. اقرأ [إرسال تشغيل](/docs/guides/submit).

## 3. المدخلات

الخطوة الثانية هي **المُدخلات**.

1. اختر **ارفع ملف CSV أو JSON أو Excel**، أو **اختيار من المكتبة** لاستخدام مجموعة بيانات محفوظة.
2. تحت **كيفية قراءة البيانات**، أعطِ كل عمود دورًا:
   - **المُدخل**: يتلقى كودك هذا العمود.
   - **المُخرج**: القيمة المتوقعة. يتلقاها المُقيِّم.
   - **تخطٍّ**: لا يستخدم Skynet هذا العمود.
3. أبقِ **استخدم التوصية** للتقسيم. في معظم مجموعات البيانات يكون التقسيم 70% للتدريب و15% للتحقق و15% للاختبار.

اقرأ [مجموعات البيانات والتقسيمات](/docs/concepts/datasets) للاطلاع على القواعد الكاملة.

## 4. المحسن

الخطوة الثالثة هي **المُحسِّن** ("المُحسِّن والنماذج والميزانية").

- أبقِ المُحسِّن على **Auto**.
- اختر **نموذج التأمل**. يستخدمه المُحسِّن لكتابة نسخ جديدة. هذا النموذج مطلوب.
- تحت **الميزانية**، أبقِ **الحد الأقصى لتشغيلات المُقيِّم** على قيمته الافتراضية 200.

اقرأ [المحرّكات](/docs/concepts/engines) لاختيار محرّك معيّن.

## 5. المقياس والتشغيل

الخطوة الأخيرة هي **المقياس والتشغيل**. يكتب المساعد المُقيِّم نيابةً عنك. ويمكنك تعديله. يتلقى المُقيِّم مسار نسخة واحدة من المستودع وحالة واحدة:

```python tab="scorer.py"
import importlib.util


def score(repo_path, case):
    spec = importlib.util.spec_from_file_location("serve", f"{repo_path}/serve.py")
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    got = str(module.serve(case["input"])).strip().lower()
    want = case["expected"]["label"].strip().lower()
    if got == want:
        return 1.0, {"feedback": "Correct label."}
    return 0.0, {"feedback": f"Expected '{want}', got '{got}'."}
```

يحتوي `case["input"]` على أعمدة الإدخال لحالة واحدة. ويحتوي `case["expected"]` على عمود الإخراج، ومفتاحه اسم العمود. في المستودع ملف `serve.py` فيه `def serve(input)`. يستخدم Skynet الدالة نفسها لتقديم أفضل نسخة بعد التشغيل.

ثم شغّل الفحص. يشغّل الفحص الإعداد والمُقيِّم على نسخة البداية في البيئة المعزولة. لا يمكنك بدء التشغيل إلا بعد نجاح الفحص.

## 6. البدء والمتابعة

تعرض شاشة الملخص "جاهز للتشغيل". علاماتها هي عام والبيانات والنماذج والميزانية والمكافأة. راجع الإعداد، ثم ابدأ التحسين.

افتح التشغيل من قائمة عمليات التحسين لمتابعته. يدفع Skynet كل نسخة مرشّحة إلى فرع خاص بها في مستودعك الجديد. يشير الفرع `skynet/best` دائمًا إلى أفضل نسخة. اقرأ [النتائج](/docs/guides/results) لفهم الدرجات والنسخة الفائزة.
