रन पेज किसी रन की प्रगति और परिणाम दिखाता है। यह गाइड रन पेज के टैब, स्कोर, और सबसे अच्छे संस्करण को निर्यात करने या सर्व करने का तरीका बताती है।

## रन पेज के टैब

रन पेज केवल वे टैब दिखाता है जो रन पर लागू होते हैं। कुछ टैब स्थिति और आपके अनुभव स्तर पर निर्भर करते हैं।

| टैब                   | कब दिखता है                                                  | इसमें क्या होता है                                                       |
| -------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------- |
| **अवलोकन**           | हमेशा                                                       | प्रगति, स्कोर और स्कोर का इतिहास                                          |
| **उपयोग**             | ऐसा सफल रन जिसकी रिपॉज़िटरी में `serve.py` फ़ाइल है               | सबसे अच्छे संस्करण को कॉल करने का एक फ़ॉर्म, और इंटीग्रेशन कोड                 |
| **आर्टिफैक्ट**         | परिणाम वाला रन                                               | आपकी रिपॉज़िटरी के संस्करण, सबसे अच्छे संस्करण के साथ                       |
| **डेटा**              | केसों वाला पूरा हुआ रन                                          | प्रशिक्षण, मान्यकरण और परीक्षण सेट में बँटा डेटा                              |
| **कोड**               | जब रन में दिखाने के लिए कोड हो                                   | स्कोरर                                                                 |
| **रिवॉर्ड**            | ऐसा रन जिसका स्कोरर रिवॉर्ड हिस्से बताता है                         | रिवॉर्ड के हिस्से और उनके weights                                          |
| **लॉग**               | ज़्यादातर रन                                                   | रन लॉग                                                                 |
| **उपयोग और लागत**      | जब आप साइन इन हों                                              | रन ने क्या खर्च किया                                                     |
| **निर्धारित रन**        | सफल रन                                                       | सबसे अच्छे संस्करण से ऑप्टिमाइज़ेशन को फिर से चलाने का शेड्यूल                   |
| **कॉन्फ़िग**            | हमेशा                                                       | रन का कॉन्फ़िगरेशन                                                       |

> **गाइडेड** स्तर पर, रन पेज **डेटा**, **कोड**, **लॉग** और **कॉन्फ़िग** टैब छिपाता है। इनमें से किसी टैब का सीधा लिंक फिर भी उसे खोलता है। स्तर **सेटिंग्स → खाता** में बदलें।

## स्कोर

Skynet मान्यकरण केस पर संस्करण चुनता है। वह अंतिम स्कोर परीक्षण केस पर रिपोर्ट करता है। इंजन परीक्षण केस कभी नहीं देखते। [डेटासेट और विभाजन](/docs/concepts/datasets) पढ़ें।

**अवलोकन** टैब दिखाता है:

- **सुधार**: शुरुआती संस्करण से सबसे अच्छे संस्करण तक का बदलाव।
- **स्कोर प्रगति**: पूरे रन के दौरान स्कोर।
- **स्कोर विवरण**: हर स्कोर, **आधाररेखा**, **ऑप्टिमाइज़ किया गया** और **बदलाव** कॉलम के साथ।

जब रन सक्रिय होता है, तो अवलोकन **बीता समय**, **शेष** और **दर** भी दिखाता है।

जब आपका स्कोरर नामित स्कोर बताता है, तो अवलोकन **नामित स्कोर** भी दिखाता है।

### जब सबसे अच्छा संस्करण शुरुआती संस्करण हो

कभी-कभी कोई भी उम्मीदवार शुरुआती संस्करण से बेहतर नहीं होता। तब Skynet शुरुआती संस्करण लौटाता है। **आर्टिफैक्ट** टैब बताता है कि एक रिग्रेशन गार्ड लागू किया गया।

अगर रन अपने बजट पर रुका, तो रन पेज बताता है कि Skynet ने कौन-सा संस्करण सहेजा। [रन](/docs/concepts/runs) पढ़ें।

## सबसे अच्छा संस्करण निर्यात करें

**आर्टिफैक्ट** टैब आपकी रिपॉज़िटरी के **संस्करण** की सूची दिखाता है। हर संस्करण के लिए आप:

- संस्करण कॉपी कर सकते हैं।
- संस्करण को फ़ाइल के रूप में डाउनलोड कर सकते हैं।
- संस्करण को पूरी रिपॉज़िटरी की zip के रूप में डाउनलोड कर सकते हैं।

आप किसी संस्करण की तुलना दूसरे संस्करण से कर सकते हैं। टैब किसी संस्करण के लिए **स्कोरर फ़ीडबैक** भी दिखाता है।

### नई रिपॉज़िटरी में ब्रांच

जब Skynet ने रन के लिए रिपॉज़िटरी बनाई, तो वह हर उम्मीदवार को उसकी अपनी ब्रांच `skynet/candidate-<version id>` में पुश करता है। `skynet/best` ब्रांच हमेशा सबसे अच्छे संस्करण की ओर इशारा करती है। बेहतर संस्करण मिलने पर यह आगे बढ़ती है।

## सबसे अच्छा संस्करण सर्व करें

आप सबसे अच्छे संस्करण को अपने कोड से कॉल कर सकते हैं। रिपॉज़िटरी के रूट में एक `serve.py` फ़ाइल होनी चाहिए जो `serve(input)` को परिभाषित करती है:

```python tab="serve.py"
def serve(input):
    return {"label": classify(input["message"])}
```

- `input` अनुरोध के इनपुट फ़ील्ड की dict है।
- रिटर्न मान JSON में बदलने योग्य होना चाहिए। एक dict, `outputs` बनती है। कोई भी दूसरा मान `{"output": value}` बनता है।
- `serve.py`, `skynet` सहायक मॉड्यूल के `llm` से मॉडल को कॉल कर सकता है। उसे रन के सीक्रेट नहीं मिलते।

Skynet सबसे अच्छे संस्करण को उसी सुरक्षित सैंडबॉक्स में चलाता है जिसमें रन चला। **उपयोग** टैब के दो हिस्से हैं:

- एक फ़ॉर्म। इनपुट फ़ील्ड भरें और परिणाम पाने के लिए **चलाएँ** चुनें।
- cURL, Python, JavaScript और Go में **इंटीग्रेशन कोड**।

सबसे अच्छे संस्करण को कॉल करने के लिए, **सेटिंग्स → API** में एक API टोकन बनाएँ। फिर एक अनुरोध भेजें। `Idempotency-Key` हेडर ज़रूरी है:

```bash tab="cURL"
export APP_API_TOKEN=skyd_...
curl -X POST "$API_URL/serve/<optimization_id>" \
  -H "Authorization: Bearer $APP_API_TOKEN" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{"inputs": {"message": "I was charged twice."}, "max_cost_cents": 5}'
```

```python tab="Python"
import os
import uuid
import requests

response = requests.post(
    f"{os.environ['API_URL']}/serve/<optimization_id>",
    headers={
        "Authorization": f"Bearer {os.environ['APP_API_TOKEN']}",
        "Idempotency-Key": str(uuid.uuid4()),
    },
    json={"inputs": {"message": "I was charged twice."}, "max_cost_cents": 5},
)
print(response.json()["outputs"])
```

`message` की जगह अपने रन के इनपुट फ़ील्ड रखें। **उपयोग** टैब पर **इंटीग्रेशन कोड** आपके लिए असली URL और फ़ील्ड के नाम भर देता है।

रिस्पॉन्स में `outputs`, `input_fields`, `output_fields`, `model_used`, `cents_charged` और `budget` होते हैं।

> [!TIP]
> हर कॉल का बिल अलग से, कॉल करने वाले के बैलेंस से कटता है। `max_cost_cents` सेंट में तय करता है कि यह एक कॉल अधिकतम कितना खर्च कर सकती है। अगर आप वही `Idempotency-Key` दोबारा भेजते हैं, तो Skynet कॉल के लिए दोबारा शुल्क नहीं लेता।

प्रमाणीकरण और दूसरे endpoints के लिए [API](/docs/api) पढ़ें।
