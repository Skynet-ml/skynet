यह पेज बताता है कि लगभग दस मिनट में अपना पहला रन कैसे शुरू करें। आप साइन इन करते हैं, एक छोटा डेटासेट अपलोड करते हैं, विज़ार्ड के चार चरण भरते हैं, और रन शुरू करते हैं। इस उदाहरण में Skynet एक नई रिपॉज़िटरी बनाता है जो सपोर्ट संदेशों को लेबल में बाँटती है, और फिर उसे बेहतर बनाता है।

## शुरू करने से पहले

आपको चाहिए:

- एक Skynet खाता।
- एक GitHub खाता। Skynet इसी खाते में रिपॉज़िटरी बनाता है।
- एक CSV, JSON या Excel फ़ाइल (`.csv`, `.json`, `.xlsx` या `.xls`)। हर पंक्ति एक केस है।
- एक या ज़्यादा इनपुट कॉलम, उदाहरण के लिए `message`।
- एक अपेक्षित-आउटपुट कॉलम, उदाहरण के लिए `label`।

> [!TIP]
> कम से कम 5 पंक्तियाँ इस्तेमाल करें। 5 से कम जोड़ों पर Skynet कोई परीक्षण सेट नहीं रखता, इसलिए अंतिम स्कोर उन्हीं केसों से आता है जिन्हें ऑप्टिमाइज़र ने इस्तेमाल किया।

## 1. साइन इन करें

Skynet में साइन इन करें। **सेटिंग्स → कनेक्टर** में GitHub जोड़ें। फिर `/submit` पर सबमिट पेज खोलें।

> [!NOTE]
> यह पेज **स्टैंडर्ड** स्तर के लेबल इस्तेमाल करता है। **गाइडेड** स्तर सरल लेबल इस्तेमाल करता है, ऑप्टिमाइज़र चरण छोड़ देता है, और आपके लिए **Auto** चुनता है। स्तर को सेटिंग्स में बदलें।

## 2. टास्क

पहला चरण **टास्क** है। यह पूछता है "आप क्या ऑप्टिमाइज़ करना चाहते हैं?"

1. **लक्ष्य** में लिखें कि अच्छा परिणाम क्या है। सरल शब्द इस्तेमाल करें, उदाहरण के लिए "हर सपोर्ट संदेश को billing, bug या other में बाँटें।"
2. वैकल्पिक: **पृष्ठभूमि** में ऐसा संदर्भ जोड़ें जो ऑप्टिमाइज़र की मदद करे।
3. **नई रिपॉज़िटरी बनाएँ** चुनें। एक नाम दर्ज करें, उदाहरण के लिए `support-labels`, और **निजी** या **सार्वजनिक** चुनें।

Skynet आपके GitHub खाते में रिपॉज़िटरी बनाता है। असिस्टेंट आपके टास्क और डेटा से पहला समाधान लिखता है। यह समाधान शुरुआती संस्करण है। अगर आपके पास पहले से कोड है, तो इसके बजाय **रिपॉज़िटरी इस्तेमाल करें** चुनें। [रन सबमिट करें](/docs/guides/submit) पढ़ें।

## 3. इनपुट

दूसरा चरण **इनपुट** है।

1. **CSV, JSON या Excel फ़ाइल अपलोड करें** चुनें, या सहेजा हुआ डेटासेट इस्तेमाल करने के लिए **लाइब्रेरी से चुनें** चुनें।
2. **डेटा कैसे पढ़ा जाए** के नीचे हर कॉलम को एक भूमिका दें:
   - **इनपुट**: आपके कोड को यह कॉलम मिलता है।
   - **आउटपुट**: अपेक्षित मान। स्कोरर को यह मिलता है।
   - **छोड़ें**: Skynet इस कॉलम का इस्तेमाल नहीं करता।
3. विभाजन के लिए **अनुशंसा का उपयोग करें** रहने दें। ज़्यादातर डेटासेट के लिए विभाजन 70% प्रशिक्षण, 15% मान्यकरण और 15% परीक्षण होता है।

पूरे नियमों के लिए [डेटासेट और विभाजन](/docs/concepts/datasets) पढ़ें।

## 4. ऑप्टिमाइज़र

तीसरा चरण **ऑप्टिमाइज़र** ("ऑप्टिमाइज़र, मॉडल और बजट") है।

- ऑप्टिमाइज़र को **Auto** पर रहने दें।
- एक **रिफ़्लेक्शन मॉडल** चुनें। ऑप्टिमाइज़र नए संस्करण लिखने के लिए इसका इस्तेमाल करता है। यह मॉडल ज़रूरी है।
- **बजट** के नीचे **अधिकतम स्कोरर रन** को उसके डिफ़ॉल्ट मान 200 पर रहने दें।

कोई खास इंजन चुनने के लिए [इंजन](/docs/concepts/engines) पढ़ें।

## 5. मेट्रिक और रन

आखिरी चरण **मेट्रिक और रन** है। असिस्टेंट आपके लिए स्कोरर लिखता है। आप उसे बदल सकते हैं। स्कोरर को रिपॉज़िटरी के एक संस्करण का पाथ और एक केस मिलता है:

```python tab="scorer.py"
import importlib.util


def score(repo_path, case):
    spec = importlib.util.spec_from_file_location("serve", f"{repo_path}/serve.py")
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    got = str(module.serve(case["input"])).strip().lower()
    want = case["expected"]["label"].strip().lower()
    if got == want:
        return 1.0, {"feedback": "Correct label."}
    return 0.0, {"feedback": f"Expected '{want}', got '{got}'."}
```

`case["input"]` में एक केस के इनपुट कॉलम होते हैं। `case["expected"]` में आउटपुट कॉलम होता है, उसके कॉलम नाम की कुंजी के साथ। रिपॉज़िटरी में `def serve(input)` वाली एक `serve.py` फ़ाइल है। रन के बाद Skynet सबसे अच्छे संस्करण को सर्व करने के लिए इसी फ़ंक्शन का इस्तेमाल करता है।

फिर जाँच चलाएँ। जाँच आपके सेटअप और आपके स्कोरर को सैंडबॉक्स में शुरुआती संस्करण पर चलाती है। जाँच पास होने के बाद ही आप रन शुरू कर सकते हैं।

## 6. शुरू करें और देखें

सारांश स्क्रीन पर "चलाने के लिए तैयार" दिखता है। इसके टैब हैं: सामान्य, डेटा, मॉडल, बजट और रिवॉर्ड। सेटअप जाँचें, फिर ऑप्टिमाइज़ेशन शुरू करें।

रन को देखने के लिए उसे अपनी ऑप्टिमाइज़ेशन सूची से खोलें। Skynet हर उम्मीदवार को आपकी नई रिपॉज़िटरी की अलग ब्रांच में पुश करता है। `skynet/best` ब्रांच हमेशा सबसे अच्छे संस्करण की ओर इशारा करती है। स्कोर और विजेता संस्करण को समझने के लिए [परिणाम](/docs/guides/results) पढ़ें।
