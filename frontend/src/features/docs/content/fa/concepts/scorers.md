امتیازدهنده به Skynet می‌گوید یک نسخه از مخزن شما چقدر خوب است. امتیازدهنده یک تابع Python در `scorer.py` است. همهٔ موتورها همین تابع را فراخوانی می‌کنند. این صفحه قرارداد، مقدار بازگشتی و چند مثال را ارائه می‌دهد.

## قرارداد

```python
def score(repo_path, case, output=None):
    ...
    return {"score": score_value, "feedback": "..."}
```

| آرگومان     | محتوای آن                                                                        |
| ----------- | -------------------------------------------------------------------------------- |
| `repo_path` | پوشه‌ای که فقط فایل‌های معیار شما را نگه می‌دارد. هیچ فایل دیگری از مخزن و هیچ کدی از نسخه در آن نیست |
| `case`      | یک dict. `case["input"]` فیلدهای ورودی را نگه می‌دارد. `case["expected"]` مقدار مورد انتظار را نگه می‌دارد، یا `None` است |
| `output`    | آنچه `entry` بخش `[run]` برای این مورد برگرداند، یا `None` وقتی فایل `[run]` ندارد |

فایل `optimize.toml` مخزن باید یک بخش `[run]` یا یک مرحلهٔ `[target.<name>]` داشته باشد. `entry` بخش `[run]` یک نسخه را روی یک مورد، در جعبهٔ ایزولهٔ خودش اجرا می‌کند. Skynet فایلی را که هیچ‌کدام را ندارد رد می‌کند، چون هر نسخه همان امتیاز را می‌گرفت.

- یک entry تابعی، مثلاً `entry = "serve.py:serve"`، مقدار `case["input"]` را به‌عنوان آرگومان می‌گیرد. `output` مقدار بازگشتی آن است.
- یک entry دستوری، مثلاً `entry = ["python", "-m", "pytest", "-q"]`، ورودی را به‌صورت JSON روی stdin می‌گیرد. `output` برابر `{"exit_code": ..., "stdout": "..."}` است.

امتیازدهنده در یک جعبهٔ ایزولهٔ جداگانه اجرا می‌شود. این جعبه فقط فایل‌های معیار شما را نگه می‌دارد. امتیازدهنده نمی‌تواند کد نسخه را import یا اجرا کند. نسخه را فقط از طریق `output`، یا از طریق `call()` به یک مرحلهٔ `[target.<name>]` می‌بیند. تابع `call` را با `from openascent import call` import کنید. صفحهٔ [بهینه‌سازی چگونه کار می‌کند](/docs/concepts/optimization) را بخوانید.

## مقدار بازگشتی

`score` یک شیء برمی‌گرداند:

```python
{
    "score": 0.78,
    "feedback": "Misses short names.",
    "scores": {
        "precision": {"score": 0.90},
        "recall": {"score": 0.69, "feedback": "Misses names under 4 letters."},
    },
}
```

- کلید `"score"` الزامی است. یک عدد متناهی است. فقط همین امتیاز نسخه‌ها را رتبه‌بندی می‌کند.
- کلید `"feedback"` یک متن اختیاری است. توصیه می‌شود، چون GEPA و Auto از آن یاد می‌گیرند. بدون بازخورد، موتورها فقط امتیازها را می‌بینند و لاگ اجرا یک بار این را می‌گوید.
- کلید `"scores"` اختیاری است. این کلید نام‌ها را به امتیازهای نام‌دار نگاشت می‌کند. هر امتیاز نام‌دار یک شیء با `"score"` خودش و یک `"feedback"` اختیاری است. هر موتور هر امتیاز نام‌دار را به‌عنوان یک هدف جداگانه به کار می‌برد.

هر شکل یا کلید دیگری خطاست. بررسی بخش نادرست و شکل معتبر را نشان می‌دهد.

| مقدار بازگشتی | معتبر |
| --- | --- |
| `{"score": 0.8, "feedback": "Close. Missing the date."}` | بله |
| `{"score": 0.8}` | بله. بازخوردی ندارد. |
| `{"score": 1.0, "scores": {"format": {"score": 1.0}}}` | بله |
| `0.8` | نه. مقدار یک شیء نیست. |
| `(0.8, "Close. Missing the date.")` | نه. مقدار یک شیء نیست. |
| `{"score": "0.8"}` | نه. امتیاز یک رشته است. |
| `{"score": 0.8, "scores": {"format": 1.0}}` | نه. امتیاز نام‌دار باید یک شیء باشد. |
| `{"score": 0.8, "feedbak": "OK"}` | نه. کلید `feedbak` ناشناخته است. |

## نوشتن بازخورد مفید

GEPA و Auto متن بازخورد را می‌خوانند تا نسخهٔ بعدی را بنویسند. بگویید چه چیزی اشتباه است و خروجی درست چه شکلی دارد.

| بازخورد ضعیف   | بازخورد مفید                                                                        |
| -------------- | ----------------------------------------------------------------------------------- |
| «اشتباه است.»  | «انتظار 'billing' بود، 'other' دریافت شد. پیام به یک برداشت از حساب اشاره می‌کند.»   |
| «قالب بد است.» | «خروجی JSON معتبر نیست. بعد از آخرین فیلد یک ویرگول اضافه دارد.»                    |

> [!NOTE]
> عامل کدنویسی هرگز کد منبع امتیازدهندهٔ شما، مقدارهای مورد انتظار یا رازهای اجرا را نمی‌بیند. فقط امتیازها و متن بازخورد را می‌بیند.

## مثال‌ها

### تطابق دقیق

```toml tab="optimize.toml"
version = 1

[run]
entry = "serve.py:serve"
```

```python tab="scorer.py"
def score(repo_path, case, output=None):
    want = case["expected"]["label"]
    if output == want:
        return {"score": 1.0, "feedback": "Correct."}
    return {"score": 0.0, "feedback": f"Expected {want!r}, got {output!r}."}
```

`case["expected"]` یک dict است که کلیدهای آن نام ستون «خروجی» شما هستند. صفحهٔ [مجموعه‌داده‌ها و تقسیم](/docs/concepts/datasets) را بخوانید.

### اجرای آزمون‌های مخزن

`entry` بخش `[run]` آزمون‌ها را اجرا می‌کند. امتیازدهنده کد خروج و خروجی آزمون‌ها را می‌خواند.

```toml tab="optimize.toml"
version = 1

[run]
entry = ["python", "-m", "pytest", "-q"]
timeout = 300
```

```python tab="scorer.py"
def score(repo_path, case, output=None):
    if output["exit_code"] == 0:
        return {"score": 1.0, "feedback": "All tests pass."}
    return {"score": 0.0, "feedback": output["stdout"][-2000:]}
```

وقتی `entry` بخش `[run]` روی یک مورد شکست می‌خورد، آن مورد امتیاز ندارد. اگر `entry` شروع نشود، از مهلت بگذرد یا یک سیگنال آن را متوقف کند، یا اگر یک `entry` از نوع تابع خطا بدهد یا پیش از برگرداندن مقدار خارج شود، بازخورد `Run failed: …` است و Skynet امتیازدهنده را فراخوانی نمی‌کند. کد خروج غیرصفر یک `entry` از نوع فرمان شکست نیست: امتیازدهنده آن را در `output` می‌گیرد. نسخه‌ای که چنین موردی دارد امتیاز ندارد. آن نسخه نمی‌تواند بهترین نسخه باشد، به هیچ `[outcome] target` نمی‌رسد و هیچ pull request باز نمی‌کند. اگر شکست باید به‌صورت یک عدد حساب شود، شکست را در برنامهٔ خودتان بگیرید، یک خروجی بنویسید و بگذارید امتیازدهنده به آن امتیاز بدهد. صفحهٔ [قواعد مخزن](https://github.com/Skynet-ml/skynet/blob/main/docs/repository-constraints.md) را بخوانید.

### مدل به‌عنوان داور

امتیازدهنده می‌تواند یک مدل را فراخوانی کند. `llm` را از ماژول کمکی `openascent` وارد کنید. فراخوانی از طریق دروازهٔ مدل Skynet به مدل امتیازدهندهٔ اجرا می‌رود.

```toml tab="optimize.toml"
version = 1

[run]
entry = "serve.py:serve"
```

```python tab="scorer.py"
from openascent import llm


def score(repo_path, case, output=None):
    verdict = llm(
        "Answer PASS or FAIL, then give one sentence of reasons.",
        input=f"Question: {case['input']['question']}\nAnswer: {output}",
        temperature=0,
        max_tokens=512,
    )
    passed = str(verdict).strip().upper().startswith("PASS")
    return {"score": 1.0 if passed else 0.0, "feedback": str(verdict)}
```

امتیازدهنده می‌تواند از هر کلاینت سازگار با OpenAI هم با متغیرهای محیطی `OPENAI_BASE_URL`، `APP_API_KEY` و `APP_MODEL` استفاده کند. دروازه فقط مدل امتیازدهندهٔ اجرا را می‌پذیرد.

## فراخوانی‌های مدل و رازها

- فراخوانی‌هایی که از کلیدهای Skynet استفاده می‌کنند از بودجهٔ اجرا اندازه‌گیری و کسر می‌شوند. با کلید خودتان (BYOK)، فراخوانی به کلید ارائه‌دهندهٔ شما می‌رود و Skynet کارمزد مدل دریافت نمی‌کند. صفحهٔ [صورت‌حساب](/docs/concepts/billing) را بخوانید.
- امتیازدهنده رازهای اجرا را به‌صورت متغیرهای محیطی نمی‌گیرد. یک راز فقط از راه یک جدول `[services.<name>]` که `[metric] services` آن را فهرست می‌کند، یا از راه یک سرور در فایل `[metric] mcp`، به امتیازدهنده می‌رسد. راز را در `headers` جدول به‌صورت `${NAME}` بنویسید. امتیازدهنده درخواست‌هایش را به URL موجود در `ASCENT_SERVICE_<NAME>_URL` می‌فرستد. Skynet راز را بیرون از محیط اجرای ایزوله اضافه می‌کند.
- ‏Skynet مقدار رازها را در خروجی امتیازدهنده و در لاگ‌ها پنهان می‌کند.
