این صفحه نشان می‌دهد چگونه اولین اجرای خود را در حدود ده دقیقه شروع کنید. وارد حساب می‌شوید، یک مجموعه‌دادهٔ کوچک بارگذاری می‌کنید، چهار مرحلهٔ ویزارد را پر می‌کنید و اجرا را شروع می‌کنید. در این مثال، Skynet یک مخزن جدید می‌سازد که پیام‌های پشتیبانی را در برچسب‌ها دسته‌بندی می‌کند، و سپس آن را بهتر می‌کند.

## پیش از شروع

به این موارد نیاز دارید:

- یک حساب Skynet.
- یک حساب GitHub. Skynet مخزن را در این حساب می‌سازد.
- یک فایل CSV، JSON یا Excel (`.csv`، `.json`، `.xlsx` یا `.xls`). هر ردیف یک مورد است.
- یک یا چند ستون ورودی، برای مثال `message`.
- یک ستون خروجی مورد انتظار، برای مثال `label`.

> [!TIP]
> دست‌کم ۵ ردیف استفاده کنید. با کمتر از ۵ جفت، Skynet مجموعهٔ آزمون نگه نمی‌دارد، پس امتیاز نهایی از موردهایی می‌آید که بهینه‌ساز از آن‌ها استفاده کرده است.

## ۱. ورود

وارد Skynet شوید. GitHub را در **تنظیمات → اتصال‌دهنده‌ها** متصل کنید. سپس صفحهٔ ارسال را در `/submit` باز کنید.

> [!NOTE]
> این صفحه از برچسب‌های سطح **استاندارد** استفاده می‌کند. سطح **راهنمایی‌شده** برچسب‌های ساده‌تری دارد، مرحلهٔ بهینه‌ساز را رد می‌کند و **Auto** را برای شما انتخاب می‌کند. سطح را در تنظیمات تغییر دهید.

## ۲. کار

مرحلهٔ اول **کار** است. این مرحله می‌پرسد «چه چیزی را می‌خواهید بهینه کنید؟»

1. در **هدف**، بنویسید نتیجهٔ خوب چیست. از کلمه‌های ساده استفاده کنید، برای مثال «هر پیام پشتیبانی را در یکی از دسته‌های صورت‌حساب، باگ یا سایر قرار بده.»
2. اختیاری: در **پیش‌زمینه**، زمینه‌ای اضافه کنید که به بهینه‌ساز کمک می‌کند.
3. **ساخت مخزن جدید** را انتخاب کنید. یک نام وارد کنید، برای مثال `support-labels`، و **خصوصی** یا **عمومی** را انتخاب کنید.

Skynet مخزن را در حساب GitHub شما می‌سازد. دستیار از روی کار و داده‌های شما یک راه‌حل اول می‌نویسد. این راه‌حل نسخهٔ شروع است. اگر از قبل کد دارید، به‌جای آن **استفاده از یک مخزن** را انتخاب کنید. [ارسال یک اجرا](/docs/guides/submit) را بخوانید.

## ۳. ورودی‌ها

مرحلهٔ دوم **ورودی‌ها** است.

1. **بارگذاری فایل CSV، JSON یا Excel** را انتخاب کنید، یا برای استفاده از یک مجموعه‌دادهٔ ذخیره‌شده **انتخاب از کتابخانه** را انتخاب کنید.
2. زیر **نحوهٔ خواندن داده**، به هر ستون یک نقش بدهید:
   - **ورودی**: کد شما این ستون را دریافت می‌کند.
   - **خروجی**: مقدار مورد انتظار. امتیازدهنده آن را دریافت می‌کند.
   - **رد کردن**: Skynet از این ستون استفاده نمی‌کند.
3. برای تقسیم، **استفاده از پیشنهاد** را نگه دارید. برای بیشتر مجموعه‌داده‌ها، تقسیم ۷۰٪ آموزش، ۱۵٪ اعتبارسنجی و ۱۵٪ آزمون است.

برای قاعده‌های کامل، [مجموعه‌داده‌ها و تقسیم‌ها](/docs/concepts/datasets) را بخوانید.

## ۴. بهینه‌ساز

مرحلهٔ سوم **بهینه‌ساز** است («بهینه‌ساز، مدل‌ها و بودجه»).

- بهینه‌ساز را روی **Auto** نگه دارید.
- یک **مدل بازاندیشی** انتخاب کنید. بهینه‌ساز از آن برای نوشتن نسخه‌های جدید استفاده می‌کند. این مدل الزامی است.
- زیر **بودجه**، **حداکثر اجراهای امتیازدهنده** را روی مقدار پیش‌فرض ۲۰۰ نگه دارید.

برای انتخاب یک موتور مشخص، [موتورها](/docs/concepts/engines) را بخوانید.

## ۵. معیار و اجرا

مرحلهٔ آخر **معیار و اجرا** است. دستیار امتیازدهنده را برای شما می‌نویسد. می‌توانید آن را ویرایش کنید. امتیازدهنده مسیر یک نسخه از مخزن و یک مورد را دریافت می‌کند:

```python tab="scorer.py"
import importlib.util


def score(repo_path, case):
    spec = importlib.util.spec_from_file_location("serve", f"{repo_path}/serve.py")
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    got = str(module.serve(case["input"])).strip().lower()
    want = case["expected"]["label"].strip().lower()
    if got == want:
        return 1.0, {"feedback": "Correct label."}
    return 0.0, {"feedback": f"Expected '{want}', got '{got}'."}
```

`case["input"]` ستون‌های ورودی یک مورد را نگه می‌دارد. `case["expected"]` ستون خروجی را نگه می‌دارد، با نام ستون به‌عنوان کلید. مخزن یک فایل `serve.py` با `def serve(input)` دارد. Skynet بعد از اجرا از همین تابع برای ارائهٔ بهترین نسخه استفاده می‌کند.

سپس بررسی را اجرا کنید. این بررسی راه‌اندازی و امتیازدهندهٔ شما را در محیط اجرا روی نسخهٔ شروع اجرا می‌کند. فقط بعد از قبولی در بررسی می‌توانید اجرا را شروع کنید.

## ۶. شروع و پیگیری

صفحهٔ خلاصه «آماده‌ی اجرا» را نشان می‌دهد. زبانه‌های آن عمومی، داده‌ها، مدل‌ها، بودجه و پاداش هستند. تنظیمات را بررسی کنید، سپس بهینه‌سازی را شروع کنید.

برای پیگیری اجرا، آن را از فهرست بهینه‌سازی‌های خود باز کنید. Skynet هر نامزد را به شاخهٔ جداگانهٔ خودش در مخزن جدید شما می‌فرستد. شاخهٔ `skynet/best` همیشه به بهترین نسخه اشاره می‌کند. برای فهمیدن امتیازها و نسخهٔ برنده، [نتیجه‌ها](/docs/guides/results) را بخوانید.
