העמוד הזה מראה איך להפעיל את הריצה הראשונה שלך בכעשר דקות. מתחברים, מעלים דאטאסט קטן, ממלאים את ארבעת השלבים של האשף ומפעילים את הריצה. בדוגמה, Skynet יוצר מאגר חדש שממיין הודעות תמיכה לתוויות, ואז משפר אותו.

## לפני שמתחילים

צריך:

- חשבון Skynet.
- חשבון GitHub. ‏Skynet יוצר את המאגר בחשבון הזה.
- קובץ CSV,‏ JSON או Excel ‏(`.csv`, `.json`, `.xlsx` או `.xls`). כל שורה היא מקרה אחד.
- עמודת קלט אחת או יותר, למשל `message`.
- עמודת פלט צפוי אחת, למשל `label`.

> [!TIP]
> יש להשתמש בלפחות 5 שורות. עם פחות מ-5 זוגות, Skynet לא שומר קבוצת בדיקה, ולכן הציון הסופי מגיע ממקרים שהאופטימייזר השתמש בהם.

## 1. התחברות

התחבר/י ל-Skynet. חבר/י את GitHub ב-**הגדרות → חיבורים**. אחר כך פתח/י את דף ההגשה ב-`/submit`.

> [!NOTE]
> העמוד הזה משתמש בתוויות של הרמה **רגיל**. הרמה **מודרך** משתמשת בתוויות פשוטות יותר, מדלגת על שלב האופטימייזר ובוחרת **Auto** בשבילך. אפשר לשנות את הרמה בהגדרות.

## 2. משימה

השלב הראשון הוא **משימה**. הוא שואל "מה תרצו לייעל?"

1. בשדה **מטרה**, כתוב/י מהי תוצאה טובה. השתמש/י במילים פשוטות, למשל "מיין כל הודעת תמיכה ל-billing,‏ bug או other."
2. אופציונלי: בשדה **רקע**, הוסף/הוסיפי הקשר שעוזר לאופטימייזר.
3. בחר/י **יצירת מאגר חדש**. הזן/הזיני שם, למשל `support-labels`, ובחר/י **פרטי** או **ציבורי**.

‏Skynet יוצר את המאגר בחשבון GitHub שלך. העוזר כותב פתרון ראשון מהמשימה ומהנתונים שלך. הפתרון הזה הוא גרסת ההתחלה. אם כבר יש לך קוד, בחר/י במקום זאת **שימוש במאגר קיים**. קרא/י את [הפעלת ריצה](/docs/guides/submit).

## 3. קלטים

השלב השני הוא **קלטים**.

1. בחר/י **העלו קובץ CSV,‏ JSON או Excel**, או **בחירה מהספרייה** כדי להשתמש בדאטאסט שמור.
2. תחת **איך לקרוא את הנתונים**, תן/תני לכל עמודה תפקיד:
   - **קלט**: הקוד שלך מקבל את העמודה הזו.
   - **פלט**: הערך הצפוי. פונקציית הניקוד מקבלת אותו.
   - **דלג/י**: Skynet לא משתמש בעמודה הזו.
3. השאר/י **לפי ההמלצה** לחלוקה. ברוב הדאטאסטים החלוקה היא 70% אימון, 15% אימות ו-15% בדיקה.

קרא/י את [דאטאסטים וחלוקה](/docs/concepts/datasets) לכל הכללים.

## 4. אופטימייזר

השלב השלישי הוא **מאפטם** ("אופטימייזר, מודלים ותקציב").

- השאר/י את האופטימייזר על **Auto**.
- בחר/י **מודל רפלקציה** (מודל האופטימיזציה). האופטימייזר משתמש בו כדי לכתוב גרסאות חדשות. המודל הזה הוא חובה.
- תחת **תקציב**, השאר/י את **מקסימום הרצות ניקוד** על ברירת המחדל, 200.

קרא/י את [מנועים](/docs/concepts/engines) כדי לבחור מנוע ספציפי.

## 5. מדד והרצה

השלב האחרון הוא **מדד והרצה**. העוזר כותב בשבילך את פונקציית הניקוד. אפשר לערוך אותה. פונקציית הניקוד מקבלת את הנתיב של גרסה אחת של המאגר ומקרה אחד:

```python tab="scorer.py"
import importlib.util


def score(repo_path, case):
    spec = importlib.util.spec_from_file_location("serve", f"{repo_path}/serve.py")
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    got = str(module.serve(case["input"])).strip().lower()
    want = case["expected"]["label"].strip().lower()
    if got == want:
        return 1.0, {"feedback": "Correct label."}
    return 0.0, {"feedback": f"Expected '{want}', got '{got}'."}
```

‏`case["input"]` מכיל את עמודות הקלט של מקרה אחד. ‏`case["expected"]` מכיל את עמודת הפלט, עם שם העמודה כמפתח. במאגר יש קובץ `serve.py` עם `def serve(input)`. ‏Skynet משתמש באותה פונקציה כדי להפעיל את הגרסה הטובה ביותר כשירות אחרי הריצה.

אחר כך הרץ/הריצי את הבדיקה. הבדיקה מריצה את ההתקנה ואת פונקציית הניקוד שלך על גרסת ההתחלה ב-sandbox. אפשר להפעיל את הריצה רק אחרי שהבדיקה עוברת.

## 6. הפעלה ומעקב

מסך הסיכום מציג "מוכן להרצה". הלשוניות שלו הן כללי, נתונים, מודלים, תקציב ותגמול. בדוק/בדקי את ההגדרות, ואז הפעל/י את האופטימיזציה.

פתח/י את הריצה מרשימת האופטימיזציות שלך כדי לעקוב אחריה. ‏Skynet דוחף כל מועמד לענף משלו במאגר החדש שלך. הענף `skynet/best` תמיד מצביע על הגרסה הטובה ביותר. קרא/י את [תוצאות](/docs/guides/results) כדי להבין את הציונים ואת הגרסה המנצחת.
