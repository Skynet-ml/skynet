עמוד הריצה מציג את ההתקדמות ואת התוצאות של ריצה. המדריך הזה מסביר את הלשוניות בעמוד הריצה, את הציונים, ואיך לייצא את הגרסה הטובה ביותר או להפעיל אותה כשירות.

## לשוניות בעמוד הריצה

עמוד הריצה מציג רק את הלשוניות שרלוונטיות לריצה. חלק מהלשוניות תלויות בסטטוס וברמת הניסיון שלך.

| לשונית           | מתי היא מופיעה                                  | מה יש בה                                                        |
| ---------------- | ----------------------------------------------- | --------------------------------------------------------------- |
| **סקירה**        | תמיד                                            | התקדמות, ציונים והיסטוריית הציונים                              |
| **שימוש**        | ריצה מוצלחת שבמאגר שלה יש קובץ `serve.py`       | טופס לקריאה לגרסה הטובה ביותר, וקוד לשילוב                      |
| **תוצר**         | ריצה עם תוצאה                                   | הגרסאות של המאגר שלך, עם הגרסה הטובה ביותר                      |
| **נתונים**       | ריצה שהסתיימה ויש בה מקרים                      | חלוקת הנתונים לסט אימון, סט אימות וסט בדיקה                     |
| **קוד**          | כשיש לריצה קוד להציג                            | פונקציית הניקוד                                                 |
| **תגמול**        | ריצה שפונקציית הניקוד שלה מגדירה רכיבי תגמול    | רכיבי התגמול והמשקלים שלהם                                      |
| **לוגים**        | רוב הריצות                                      | הלוג של הריצה                                                   |
| **שימוש ועלות**  | בזמן התחברות                                    | כמה הריצה הוציאה                                                |
| **ריצה מתוזמנת** | ריצה מוצלחת                                     | לוח זמנים להרצת האופטימיזציה שוב מהגרסה הטובה ביותר             |
| **הגדרות**       | תמיד                                            | התצורה של הריצה                                                 |

> [!NOTE]
> ברמה **מודרך**, עמוד הריצה מסתיר את הלשוניות **נתונים**, **קוד**, **לוגים** ו-**הגדרות**. קישור ישיר ללשונית כזו עדיין פותח אותה. אפשר לשנות את הרמה ב-**הגדרות → חשבון**.

## ציונים

Skynet בוחר גרסאות לפי מקרי האימות. הוא מדווח את הציון הסופי לפי מקרי הבדיקה. המנועים אף פעם לא רואים את מקרי הבדיקה. קרא/י את [דאטאסטים וחלוקה](/docs/concepts/datasets).

הלשונית **סקירה** מציגה:

- **שיפור**: השינוי מגרסת ההתחלה לגרסה הטובה ביותר.
- **מהלך הציונים**: הציון לאורך הריצה.
- **פירוט הציון**: כל ציון, עם העמודות **בסיס**, **משופר** ו-**שינוי**.

בזמן שהריצה פעילה, הסקירה מציגה גם **זמן שעבר**, **נותר** ו-**קצב**.

הסקירה מציגה גם **ציונים בעלי שם** כשפונקציית הניקוד שלך מדווחת ציונים בעלי שם.

### כשהגרסה הטובה ביותר היא גרסת ההתחלה

לפעמים אף מועמד לא עוקף את גרסת ההתחלה. במקרה כזה Skynet מחזיר את גרסת ההתחלה. הלשונית **תוצר** מציינת שהופעל מנגנון הגנה מפני נסיגה.

אם הריצה נעצרה בגלל התקציב, עמוד הריצה מציין איזו גרסה Skynet שמר. קרא/י את [ריצות](/docs/concepts/runs).

## ייצוא הגרסה הטובה ביותר

הלשונית **תוצר** מציגה את ה**גרסאות** של המאגר שלך. לכל גרסה אפשר:

- להעתיק את הגרסה.
- להוריד את הגרסה כקובץ.
- להוריד את הגרסה כקובץ zip של כל המאגר.

אפשר להשוות גרסה לגרסה אחרת. הלשונית מציגה גם את **משוב המדד** של כל גרסה.

### ענפים במאגר חדש

כש-Skynet יצר את המאגר עבור הריצה, הוא דוחף כל מועמד לענף (branch) משלו, `skynet/candidate-<version id>`. הענף `skynet/best` תמיד מצביע על הגרסה הטובה ביותר. הוא זז כשמופיעה גרסה טובה יותר.

## הפעלת הגרסה הטובה ביותר כשירות

אפשר לקרוא לגרסה הטובה ביותר מהקוד שלך. במאגר חייב להיות קובץ `serve.py` בתיקיית השורש, שמגדיר את `serve(input)`:

```python tab="serve.py"
def serve(input):
    return {"label": classify(input["message"])}
```

- `input` הוא ה-dict של שדות הקלט מהבקשה.
- ערך ההחזרה חייב להיות ניתן להמרה ל-JSON. dict הופך ל-`outputs`. כל ערך אחר הופך ל-`{"output": value}`.
- `serve.py` יכול לקרוא למודל עם `llm` מהמודול `skynet`. הוא לא מקבל את הסודות של הריצה.

Skynet מריץ את הגרסה הטובה ביותר באותו sandbox מוגן שבו רצה הריצה. בלשונית **שימוש** יש שני חלקים:

- טופס. הזן/הזיני את שדות הקלט ובחר/י **הרץ/הריצי** כדי לקבל תוצאה.
- **קוד לשילוב** ב-cURL,‏ Python,‏ JavaScript ו-Go.

כדי לקרוא לגרסה הטובה ביותר, צור/צרי טוקן API ב-**הגדרות → API**. אחר כך שלח/י בקשה. הכותרת `Idempotency-Key` היא חובה:

```bash tab="cURL"
export APP_API_TOKEN=skyd_...
curl -X POST "$API_URL/serve/<optimization_id>" \
  -H "Authorization: Bearer $APP_API_TOKEN" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{"inputs": {"message": "I was charged twice."}, "max_cost_cents": 5}'
```

```python tab="Python"
import os
import uuid
import requests

response = requests.post(
    f"{os.environ['API_URL']}/serve/<optimization_id>",
    headers={
        "Authorization": f"Bearer {os.environ['APP_API_TOKEN']}",
        "Idempotency-Key": str(uuid.uuid4()),
    },
    json={"inputs": {"message": "I was charged twice."}, "max_cost_cents": 5},
)
print(response.json()["outputs"])
```

החלף/החליפי את `message` בשדות הקלט של הריצה שלך. **קוד לשילוב** בלשונית **שימוש** ממלא בשבילך את הכתובת האמיתית ואת שמות השדות.

התשובה מכילה את `outputs`, את `input_fields`, את `output_fields`, את `model_used`, את `cents_charged` ואת `budget`.

> [!TIP]
> כל קריאה מחויבת בנפרד, מהיתרה של הגורם הקורא. ‏`max_cost_cents` קובע את העלות המרבית של הקריאה הזו, בסנטים. אם שולחים שוב את אותו `Idempotency-Key`, ‏Skynet לא מחייב שוב על הקריאה.

קרא/י את [API](/docs/api) לגבי אימות ולגבי שאר ה-endpoints.
