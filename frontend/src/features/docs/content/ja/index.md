Skynet は、すでにお持ちのコード、または Skynet が書くコードを改善します。Skynet は Optimize Anything です。すべての実行はリポジトリを最適化します。リポジトリ、ケースのセット、スコアラーを渡すと、Skynet はリポジトリの新しいバージョンを提案し、各バージョンをスコアラーで採点して、最も良いバージョンを残します。

## Skynet が最適化するもの

すべての実行はリポジトリを最適化します。開始方法は 2 つあります。

| 開始方法                   | 起きること                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| 既存のリポジトリを使う           | Skynet は、接続した GitHub リポジトリ内の、変更を許可したパスにあるファイルを変更します。        |
| 新しいリポジトリを作成する | タスクとデータを渡します。Skynet はあなたのアカウントに新しい GitHub リポジトリを作成し、最初の解決策を書きます。 |

リポジトリのコードは何でもかまいません。プロンプトパイプライン、エージェントハーネス、スクリプト、ライブラリなどです。どのライブラリでも使えます。

すべての実行は同じコントラクトに従います。スコアラーは `score(repo_path, case)` を定義します。スコアラーはスコアと文章によるフィードバックを返します。オプティマイザーはそのフィードバックを読んで、次のバージョンをより良くします。

> [!NOTE]
> 各バージョンはサンドボックス内で動作します。バージョンを書くコーディングエージェントからは、スコアラーのソースや期待値を見ることはできません。

## 1 つのプロダクト、多数のエンジン

**Auto** はすべての実行の既定です。GEPA、AutoResearch、Meta-Harness、AutoSaddler、ShinkaEvolve を試し、その後、最も良いバージョンから GEPA を続けます。エンジンを 1 つ選ぶこともできます。GEPA、Best-of-N、AutoResearch、Meta-Harness、AutoSaddler、ShinkaEvolve のいずれかです。[最適化の仕組み](/docs/concepts/optimization) と [エンジン](/docs/concepts/engines) を参照してください。

## 実行の流れ

1. タスクを説明し、リポジトリを選ぶか、Skynet にリポジトリの作成を依頼します。
2. ケースを渡します。Skynet はそれを学習・検証・テストのセットに分割します。
3. オプティマイザー、モデル、予算を選択します。
4. スコアラーを書きます。セットアップチェックが開始バージョンでスコアラーを実行します。
5. Skynet が最適化を実行し、結果を表示します。

Skynet は検証ケースでバージョンを選びます。最終スコアはテストケースで報告します。エンジンがテストケースを見ることはありません。
