このページでは、約 10 分で最初の実行を開始する方法を説明します。サインインし、小さなデータセットをアップロードし、ウィザードの 4 つのステップに入力して、実行を開始します。例では、Skynet がサポートメッセージをラベルに分類する新しいリポジトリを作成し、それを改善します。

## 始める前に

以下が必要です。

- Skynet アカウント。
- GitHub アカウント。Skynet はこのアカウントにリポジトリを作成します。
- CSV、JSON、または Excel ファイル（`.csv`、`.json`、`.xlsx`、`.xls`）。各行が 1 つのケースです。
- 1 つ以上の入力列（例: `message`）。
- 期待される出力の列 1 つ（例: `label`）。

> [!TIP]
> 少なくとも 5 行を用意してください。ペアが 5 つ未満の場合、Skynet はテストセットを残さないため、最終スコアはオプティマイザーが使ったケースから算出されます。

## 1. サインイン

Skynet にサインインします。**設定 → コネクタ** で GitHub を接続します。次に、送信ページ `/submit` を開きます。

> [!NOTE]
> このページでは **標準** レベルのラベルを使います。**ガイド付き** レベルはよりシンプルなラベルを使い、オプティマイザーのステップを省略して、自動で **Auto** を選択します。レベルは設定で変更できます。

## 2. タスク

最初のステップは **タスク** です。「何を最適化しますか？」と尋ねられます。

1. **目的** に、良い結果とは何かを書きます。わかりやすい言葉で書いてください。例: 「各サポートメッセージを billing、bug、other のいずれかに分類する。」
2. 任意: **背景** に、オプティマイザーの助けになる補足情報を追加します。
3. **新しいリポジトリを作成** を選択します。名前（例: `support-labels`）を入力し、**非公開** または **公開** を選択します。

Skynet はあなたの GitHub アカウントにリポジトリを作成します。アシスタントは、タスクとデータから最初の解決策を書きます。この解決策が開始バージョンです。すでにコードがある場合は、代わりに **既存のリポジトリを使う** を選択します。[実行を開始する](/docs/guides/submit) をお読みください。

## 3. 入力

2 番目のステップは **入力** です。

1. **CSV、JSON、Excel ファイルをアップロード** を選択するか、保存済みのデータセットを使う場合は **ライブラリから選択** を選択します。
2. **データの読み取り方** で、各列に役割を割り当てます。
   - **入力**: コードがこの列を受け取ります。
   - **出力**: 期待値です。スコアラーがこれを受け取ります。
   - **スキップ**: Skynet はこの列を使いません。
3. 分割は **推奨を使用** のままにします。ほとんどのデータセットでは、学習 70%、検証 15%、テスト 15% に分割されます。

詳しいルールは [データセットと分割](/docs/concepts/datasets) をお読みください。

## 4. オプティマイザー

3 番目のステップは **オプティマイザー**（「オプティマイザー、モデル、予算」）です。

- オプティマイザーは **Auto** のままにします。
- **リフレクションモデル** を選択します。オプティマイザーはこのモデルを使って新しいバージョンを書きます。このモデルは必須です。
- **予算** では、**最大スコアラー実行回数** を既定値の 200 のままにします。

特定のエンジンを選ぶには、[エンジン](/docs/concepts/engines) をお読みください。

## 5. メトリクスと実行

最後のステップは **メトリクスと実行** です。アシスタントがスコアラーを書きます。あなたはそれを編集できます。スコアラーは、リポジトリの 1 つのバージョンのパスと 1 つのケースを受け取ります。

```python tab="scorer.py"
import importlib.util


def score(repo_path, case):
    spec = importlib.util.spec_from_file_location("serve", f"{repo_path}/serve.py")
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    got = str(module.serve(case["input"])).strip().lower()
    want = case["expected"]["label"].strip().lower()
    if got == want:
        return 1.0, {"feedback": "Correct label."}
    return 0.0, {"feedback": f"Expected '{want}', got '{got}'."}
```

`case["input"]` は 1 つのケースの入力列を保持します。`case["expected"]` は出力列を、その列名をキーとして保持します。リポジトリには `def serve(input)` を持つ `serve.py` ファイルがあります。Skynet は実行の後、同じ関数を使って最も良いバージョンを提供します。

次に、チェックを実行します。チェックは、サンドボックス内の開始バージョンでセットアップとスコアラーを実行します。実行を開始できるのは、チェックに合格した後だけです。

## 6. 開始して見守る

サマリー画面に「実行の準備ができました」と表示されます。タブは 全般、データ、モデル、予算、報酬 です。設定を確認してから、最適化を開始します。

実行を見守るには、最適化の一覧から実行を開きます。Skynet は各候補を、新しいリポジトリ内のそれぞれのブランチにプッシュします。`skynet/best` ブランチは常に最も良いバージョンを指します。スコアと勝ち残ったバージョンについては、[結果](/docs/guides/results) をお読みください。
