Ця сторінка показує, як почати свій перший запуск приблизно за десять хвилин. Ви входите в систему, завантажуєте невеликий набір даних, заповнюєте чотири кроки майстра й запускаєте оптимізацію. У прикладі Skynet створює новий репозиторій, який розподіляє повідомлення служби підтримки за мітками, а потім покращує його.

## Перед початком

Вам потрібні:

- Акаунт Skynet.
- Акаунт GitHub. Skynet створює репозиторій у цьому акаунті.
- Файл CSV, JSON або Excel (`.csv`, `.json`, `.xlsx` або `.xls`). Кожен рядок — це один кейс.
- Один або кілька вхідних стовпців, наприклад `message`.
- Один стовпець з очікуваним результатом, наприклад `label`.

> [!TIP]
> Використовуйте щонайменше 5 рядків. Якщо пар менше ніж 5, Skynet не виділяє тестову вибірку, і підсумкова оцінка походить із кейсів, які використовував оптимізатор.

## 1. Вхід

Увійдіть у Skynet. Підключіть GitHub у **Налаштування → Конектори**. Потім відкрийте сторінку надсилання за адресою `/submit`.

> [!NOTE]
> На цій сторінці використано підписи рівня **Стандартний**. Рівень **З підказками** має простіші підписи, пропускає крок «Оптимізатор» і обирає **Auto** за вас. Рівень можна змінити в налаштуваннях.

## 2. Завдання

Перший крок — **Завдання**. Він запитує: «Що ви хочете оптимізувати?»

1. У полі **Мета** опишіть, яким є добрий результат. Пишіть простими словами, наприклад: «Віднеси кожне повідомлення служби підтримки до категорії billing, bug або other».
2. Необов’язково: у полі **Контекст** додайте відомості, які допоможуть оптимізатору.
3. Оберіть **Створити новий репозиторій**. Введіть назву, наприклад `support-labels`, і оберіть **Приватний** або **Публічний**.

Skynet створює репозиторій у вашому акаунті GitHub. Асистент пише перше рішення на основі вашого завдання й даних. Це рішення — початкова версія. Якщо у вас уже є код, натомість оберіть **Використати репозиторій**. Прочитайте [Запуск через майстер](/docs/guides/submit).

## 3. Вхідні дані

Другий крок — **Вхідні дані**.

1. Оберіть **Завантажте файл CSV, JSON або Excel** або **Вибрати з бібліотеки**, щоб використати збережений набір даних.
2. У розділі **Як читати дані** призначте кожному стовпцю роль:
   - **Вхід**: ваш код отримує цей стовпець.
   - **Вихід**: очікуване значення. Його отримує оцінювач.
   - **Пропустити**: Skynet не використовує цей стовпець.
3. Для розбиття залиште **Використати рекомендацію**. Для більшості наборів даних розбиття становить 70% навчальних, 15% валідаційних і 15% тестових кейсів.

Повні правила наведено в розділі [Набори даних і розбиття](/docs/concepts/datasets).

## 4. Оптимізатор

Третій крок — **Оптимізатор** («Оптимізатор, моделі та бюджет»).

- Залиште оптимізатор на **Auto**.
- Оберіть **Модель рефлексії**. Оптимізатор використовує її, щоб писати нові версії. Ця модель обов’язкова.
- У розділі **Бюджет** залиште для **Макс. запусків оцінювача** типове значення 200.

Щоб обрати конкретний рушій, прочитайте [Рушії](/docs/concepts/engines).

## 5. Метрика й запуск

Останній крок — **Метрика й запуск**. Асистент пише оцінювач за вас. Ви можете його змінити. Оцінювач отримує шлях до однієї версії репозиторію й один кейс:

```python tab="scorer.py"
import importlib.util


def score(repo_path, case):
    spec = importlib.util.spec_from_file_location("serve", f"{repo_path}/serve.py")
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    got = str(module.serve(case["input"])).strip().lower()
    want = case["expected"]["label"].strip().lower()
    if got == want:
        return 1.0, {"feedback": "Correct label."}
    return 0.0, {"feedback": f"Expected '{want}', got '{got}'."}
```

`case["input"]` містить вхідні стовпці одного кейсу. `case["expected"]` містить вихідний стовпець, ключем якого є назва стовпця. Репозиторій має файл `serve.py` з `def serve(input)`. Після запуску Skynet використовує ту саму функцію, щоб обслуговувати найкращу версію.

Потім запустіть перевірку. Перевірка запускає ваше налаштування й ваш оцінювач на початковій версії в пісочниці. Запуск можна почати лише після того, як перевірка пройде успішно.

## 6. Запуск і спостереження

На екрані підсумку відображається «Готово до запуску». Його вкладки: «Загальне», «Дані», «Моделі», «Бюджет» і «Винагорода». Перевірте налаштування, а потім запустіть оптимізацію.

Щоб стежити за запуском, відкрийте його зі списку своїх оптимізацій. Skynet надсилає кожного кандидата в окрему гілку вашого нового репозиторію. Гілка `skynet/best` завжди вказує на найкращу версію. Прочитайте [Читання результатів](/docs/guides/results), щоб зрозуміти оцінки й переможну версію.
