Сторінка запуску показує перебіг і результати запуску. У цьому посібнику пояснено вкладки сторінки запуску, оцінки, а також як експортувати або розгорнути найкращу версію.

## Вкладки сторінки запуску

Сторінка запуску показує лише ті вкладки, які стосуються запуску. Деякі вкладки залежать від статусу та вашого рівня досвіду.

| Вкладка                         | Коли показується                                              | Що містить                                                            |
| ------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------- |
| **Огляд**                       | Завжди                                                        | Перебіг, оцінки та історію оцінок                                     |
| **Використання**                | Успішний запуск, репозиторій якого має файл `serve.py`        | Форму для виклику найкращої версії та код інтеграції                  |
| **Артефакт**                    | Запуск із результатом                                         | Версії вашого репозиторію разом із найкращою версією                  |
| **Дані**                        | Завершений запуск із кейсами                                  | Дані, розбиті на навчальний, валідаційний і тестовий набори           |
| **Код**                         | Коли запуск має код для показу                                | Оцінювач                                                              |
| **Винагорода**                  | Запуск, оцінювач якого оголошує частини винагороди            | Частини винагороди та їхні ваги                                       |
| **Журнали**                     | Більшість запусків                                            | Журнал запуску                                                        |
| **Використання та вартість**    | Коли ви ввійшли в систему                                     | Скільки витратив запуск                                               |
| **Запуск за розкладом**         | Успішний запуск                                               | Розклад для повторного запуску оптимізації з найкращої версії         |
| **Конфігурація**                | Завжди                                                        | Конфігурацію запуску                                                  |

> [!NOTE]
> На рівні **З підказками** сторінка запуску приховує вкладки **Дані**, **Код**, **Журнали** і **Конфігурація**. Пряме посилання на одну з цих вкладок усе одно її відкриває. Змініть рівень у **Налаштування → Обліковий запис**.

## Оцінки

Skynet вибирає версії за валідаційними прикладами. Фінальну оцінку він повідомляє за тестовими прикладами. Рушії ніколи не бачать тестових прикладів. Прочитайте [Набори даних і розбиття](/docs/concepts/datasets).

Вкладка **Огляд** показує:

- **Покращення**: зміну від початкової версії до найкращої.
- **Динаміка оцінки**: оцінку протягом запуску.
- **Розбивка оцінки**: кожну оцінку зі стовпцями **Базовий рівень**, **Оптимізовано** і **Зміна**.

Поки запуск активний, огляд також показує **Минуло**, **Залишилося** і **Темп**.

Огляд також показує **Іменовані оцінки**, коли ваш оцінювач повідомляє іменовані оцінки.

### Коли найкраща версія — це початкова версія

Іноді жоден кандидат не перевершує початкову версію. Тоді Skynet повертає початкову версію. Вкладка **Артефакт** повідомляє, що спрацював захист від регресії.

Якщо запуск зупинився, вичерпавши бюджет, сторінка запуску повідомляє, яку версію зберіг Skynet. Прочитайте [Запуски](/docs/concepts/runs).

## Експорт найкращої версії

Вкладка **Артефакт** показує **Версії** вашого репозиторію. Для кожної версії можна:

- Скопіювати версію.
- Завантажити версію як файл.
- Завантажити версію як zip-архів усього репозиторію.

Версію можна порівняти з іншою версією. Вкладка також показує **Відгук оцінювача** для версії.

### Гілки в новому репозиторії

Коли Skynet створив репозиторій для запуску, він надсилає кожного кандидата в окрему гілку `skynet/candidate-<version id>`. Гілка `skynet/best` завжди вказує на найкращу версію. Вона переміщується, коли з’являється краща версія.

## Розгортання найкращої версії

Найкращу версію можна викликати з власного коду. Репозиторій має містити в корені файл `serve.py`, який визначає `serve(input)`:

```python tab="serve.py"
def serve(input):
    return {"label": classify(input["message"])}
```

- `input` — це словник вхідних полів із запиту.
- Значення, яке повертає функція, має серіалізуватися в JSON. Словник стає `outputs`. Будь-яке інше значення стає `{"output": value}`.
- `serve.py` може викликати модель через `llm` з допоміжного модуля `skynet`. Секрети запуску він не отримує.

Skynet виконує найкращу версію в тій самій захищеній пісочниці, що й запуск. Вкладка **Використання** має дві частини:

- Форма. Введіть вхідні поля й виберіть **Запустити**, щоб отримати результат.
- **Код інтеграції** на cURL, Python, JavaScript і Go.

Щоб викликати найкращу версію, створіть API-токен у **Налаштування → API**. Потім надішліть запит. Заголовок `Idempotency-Key` обов’язковий:

```bash tab="cURL"
export APP_API_TOKEN=skyd_...
curl -X POST "$API_URL/serve/<optimization_id>" \
  -H "Authorization: Bearer $APP_API_TOKEN" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{"inputs": {"message": "I was charged twice."}, "max_cost_cents": 5}'
```

```python tab="Python"
import os
import uuid
import requests

response = requests.post(
    f"{os.environ['API_URL']}/serve/<optimization_id>",
    headers={
        "Authorization": f"Bearer {os.environ['APP_API_TOKEN']}",
        "Idempotency-Key": str(uuid.uuid4()),
    },
    json={"inputs": {"message": "I was charged twice."}, "max_cost_cents": 5},
)
print(response.json()["outputs"])
```

Замініть `message` на вхідні поля вашого запуску. **Код інтеграції** на вкладці **Використання** підставляє справжню URL-адресу та назви полів за вас.

Відповідь містить `outputs`, `input_fields`, `output_fields`, `model_used`, `cents_charged` і `budget`.

> [!TIP]
> Кожен виклик тарифікується окремо, з балансу того, хто викликає. `max_cost_cents` задає максимальну вартість одного виклику в центах. Якщо ви знову надішлете той самий `Idempotency-Key`, Skynet не стягне плату за виклик повторно.

Прочитайте [API](/docs/api) про автентифікацію та інші ендпоінти.
