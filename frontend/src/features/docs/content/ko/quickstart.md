이 페이지는 약 10분 만에 첫 실행을 시작하는 방법을 보여 줍니다. 로그인하고, 작은 데이터셋을 업로드하고, 마법사의 네 단계를 채운 뒤 실행을 시작합니다. 예제에서 Skynet은 지원 메시지를 라벨로 분류하는 새 리포지토리를 만든 다음 이를 개선합니다.

## 시작하기 전에

다음이 필요합니다.

- Skynet 계정.
- GitHub 계정. Skynet은 이 계정에 리포지토리를 만듭니다.
- CSV, JSON 또는 Excel 파일(`.csv`, `.json`, `.xlsx` 또는 `.xls`). 각 행이 하나의 케이스입니다.
- 하나 이상의 입력 열(예: `message`).
- 하나의 기대 출력 열(예: `label`).

> [!TIP]
> 최소 5개 행을 사용하세요. 쌍이 5개보다 적으면 Skynet은 테스트 세트를 따로 두지 않으므로, 최종 점수는 옵티마이저가 이미 사용한 케이스에서 나옵니다.

## 1. 로그인

Skynet에 로그인합니다. **설정 → 커넥터**에서 GitHub를 연결합니다. 그런 다음 `/submit`에서 제출 페이지를 엽니다.

> [!NOTE]
> 이 페이지는 **표준** 수준의 라벨을 사용합니다. **가이드** 수준은 더 간단한 라벨을 사용하고, 옵티마이저 단계를 건너뛰며, **Auto**를 자동으로 선택합니다. 수준은 설정에서 바꿀 수 있습니다.

## 2. 작업

첫 번째 단계는 **작업**입니다. 이 단계는 "무엇을 최적화하시겠어요?"라고 묻습니다.

1. **목표**에 좋은 결과가 무엇인지 적습니다. 쉬운 말로 적으세요. 예: "각 지원 메시지를 billing, bug, other 중 하나로 분류합니다."
2. 선택 사항: **배경**에 옵티마이저에 도움이 되는 맥락을 추가합니다.
3. **새 저장소 만들기**를 선택합니다. 이름(예: `support-labels`)을 입력하고 **비공개** 또는 **공개**를 선택합니다.

Skynet은 GitHub 계정에 리포지토리를 만듭니다. 어시스턴트는 작업과 데이터로 첫 번째 해결책을 작성합니다. 이 해결책이 시작 버전입니다. 이미 코드가 있다면 대신 **저장소 사용**을 선택합니다. [마법사로 실행 시작](/docs/guides/submit)을 읽어 보세요.

## 3. 입력

두 번째 단계는 **입력**입니다.

1. **CSV, JSON 또는 Excel 파일 업로드**를 선택하거나, 저장된 데이터셋을 쓰려면 **라이브러리에서 선택**을 선택합니다.
2. **데이터를 읽는 방식**에서 각 열에 역할을 지정합니다.
   - **입력**: 코드가 이 열을 받습니다.
   - **출력**: 기댓값입니다. 채점기가 이 열을 받습니다.
   - **건너뛰기**: Skynet이 이 열을 사용하지 않습니다.
3. 분할은 **추천 사용**을 유지합니다. 대부분의 데이터셋에서 분할은 학습 70%, 검증 15%, 테스트 15%입니다.

전체 규칙은 [데이터셋과 분할](/docs/concepts/datasets)을 읽어 보세요.

## 4. 옵티마이저

세 번째 단계는 **옵티마이저**("옵티마이저, 모델, 예산")입니다.

- 옵티마이저는 **Auto**로 둡니다.
- **리플렉션 모델**을 선택합니다. 옵티마이저는 이 모델로 새 버전을 작성합니다. 이 모델은 필수입니다.
- **예산**에서 **최대 스코어러 실행 횟수**를 기본값 200으로 둡니다.

특정 엔진을 고르려면 [엔진](/docs/concepts/engines)을 읽어 보세요.

## 5. 메트릭 및 실행

마지막 단계는 **메트릭 및 실행**입니다. 어시스턴트가 채점기를 작성합니다. 직접 수정할 수 있습니다. 채점기는 리포지토리의 한 버전 경로와 케이스 하나를 받습니다.

```python tab="scorer.py"
import importlib.util


def score(repo_path, case):
    spec = importlib.util.spec_from_file_location("serve", f"{repo_path}/serve.py")
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    got = str(module.serve(case["input"])).strip().lower()
    want = case["expected"]["label"].strip().lower()
    if got == want:
        return 1.0, {"feedback": "Correct label."}
    return 0.0, {"feedback": f"Expected '{want}', got '{got}'."}
```

`case["input"]`는 케이스 하나의 입력 열을 담습니다. `case["expected"]`는 출력 열을 열 이름을 키로 하여 담습니다. 리포지토리에는 `def serve(input)`이 있는 `serve.py` 파일이 있습니다. Skynet은 실행 후 같은 함수로 가장 좋은 버전을 서빙합니다.

그런 다음 검사를 실행합니다. 검사는 샌드박스의 시작 버전에서 설정과 채점기를 실행합니다. 검사를 통과한 후에만 실행을 시작할 수 있습니다.

## 6. 시작하고 지켜보기

요약 화면에 "실행 준비 완료"가 표시됩니다. 탭은 일반, 데이터, 모델, 예산, 보상입니다. 설정을 확인한 다음 최적화를 시작합니다.

실행을 지켜보려면 최적화 목록에서 실행을 엽니다. Skynet은 각 후보를 새 리포지토리의 별도 브랜치에 푸시합니다. `skynet/best` 브랜치는 항상 가장 좋은 버전을 가리킵니다. 점수와 우승 버전을 이해하려면 [결과 읽기](/docs/guides/results)를 읽어 보세요.
