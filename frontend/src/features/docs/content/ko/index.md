Skynet은 이미 가지고 있는 코드나 Skynet이 직접 작성한 코드를 개선합니다. Skynet은 Optimize Anything입니다. 모든 실행은 리포지토리를 최적화합니다. 리포지토리, 케이스 세트, 채점기를 제공하면 Skynet이 리포지토리의 새 버전을 제안하고, 각 버전을 채점기로 채점한 뒤 가장 좋은 버전을 유지합니다.

## Skynet이 최적화하는 대상

모든 실행은 리포지토리를 최적화합니다. 시작하는 방법은 두 가지입니다.

| 시작 방법              | 일어나는 일                                                                                     |
| ---------------------- | ----------------------------------------------------------------------------------------------- |
| 저장소 사용        | Skynet은 연결한 GitHub 리포지토리에서 변경을 허용한 경로의 파일을 변경합니다.                   |
| 새 저장소 만들기   | 작업과 데이터를 제공합니다. Skynet은 계정에 새 GitHub 리포지토리를 만들고 첫 번째 해결책을 작성합니다. |

리포지토리의 코드는 무엇이든 될 수 있습니다. 프롬프트 파이프라인, 에이전트 하네스, 스크립트, 라이브러리 등입니다. 어떤 라이브러리든 사용할 수 있습니다.

모든 실행은 같은 계약을 따릅니다. 채점기는 `score(repo_path, case)`를 정의합니다. 채점기는 점수와 서술형 피드백을 반환합니다. 옵티마이저는 이 피드백을 읽고 다음 버전을 더 좋게 만듭니다.

> [!NOTE]
> 각 버전은 샌드박스 안에서 실행됩니다. 버전을 작성하는 코딩 에이전트는 채점기 소스나 기댓값을 볼 수 없습니다.

## 하나의 제품, 여러 엔진

**Auto**는 모든 실행의 기본값입니다. GEPA, AutoResearch, Meta-Harness, AutoSaddler, ShinkaEvolve를 시도한 다음, 가장 좋은 버전에서 GEPA를 이어 갑니다. 엔진 하나를 선택할 수도 있습니다: GEPA, Best-of-N, AutoResearch, Meta-Harness, AutoSaddler 또는 ShinkaEvolve. [최적화의 작동 방식](/docs/concepts/optimization) 및 [엔진](/docs/concepts/engines) 문서를 참고하세요.

## 실행의 작동 방식

1. 작업을 설명하고, 리포지토리를 고르거나 Skynet에 새 리포지토리를 만들도록 요청합니다.
2. 케이스를 제공합니다. Skynet은 케이스를 학습, 검증, 테스트 세트로 분할합니다.
3. 옵티마이저, 모델, 예산을 선택합니다.
4. 채점기를 작성합니다. 설정 검사가 시작 버전에서 채점기를 실행합니다.
5. Skynet이 최적화를 실행하고 결과를 보여 줍니다.

Skynet은 검증 케이스에서 버전을 선택합니다. 최종 점수는 테스트 케이스에서 보고합니다. 엔진은 테스트 케이스를 절대 보지 않습니다.
